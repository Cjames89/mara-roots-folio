# CONSTRAINTS.md

Operating rules for connorselfridge.com. Read this before making any change.
This file, not chat history, is the source of truth.

---

## 1. Source of truth and branches

| Branch | Role | Editable |
|---|---|---|
| `main` | Single source of truth. All edits land here. | Yes |
| `gh-pages` | Build output. Regenerated by CI on every push to `main`. | Never hand-edit |

`index.html` is the entire site. One file, inline CSS, no partials.

---

## 2. Hard technical constraints

- Single file. All CSS lives in the `<style>` block inside `index.html`.
- No React, no framework, no npm, no build step, no bundler.
- No JavaScript. Smooth scroll is CSS (`scroll-behavior: smooth`) and stays that way.
- Only permitted external dependency: Google Fonts.
- Fully responsive. No horizontal scroll at 375px.
- `index.html` stays under 50KB, excluding fonts and images.

---

## 3. Design tokens

Defined on `:root` in `index.html`. Never introduce a color outside this set.

```
--bg     #FAF8F5   warm off-white background
--text   #1A1A1A   dark charcoal, never pure black
--muted  #6B7280   dates, captions, meta
--accent #1B2A41   deep navy, links and subtle accents only
--rule   #E5E5E5   hairline dividers
```

Typography:

- EB Garamond (serif): name, section headers, article titles (italic), project titles
- Inter (sans): all body copy
- Name: 48px desktop, 32px mobile
- Section headers: 28px, sentence case, weight 500. Not bold, not all-caps.
- Body: 17px, line-height 1.6
- Max measure: ~62ch

Banned outright: cards, boxes, rounded containers, shadows, gradients, neon,
glow, monospace, skill bubble tags, terminal brackets, emoji, stock icons,
icon fonts, buttons, and in-body download CTAs.

---

## 4. Em-dash policy

Banned in **prose only**:

- article body copy
- deks
- Now section copy
- opener thesis lines

**Preserved as-is. Do not redesign these:**

- Experience bullet glyph: `.role-points li::before { content: "—" }`
- `Role Title — Company Name` separators
- `Degree — University` separators

In prose, use commas, colons, or parentheses instead.

---

## 5. MARA policy

The employer **name stays** everywhere it currently appears, unchanged:
hero positioning line, `<meta name="description">`, `og:description`, and the
Experience section.

The ban is on **MARA work product**. Never publish:

- pipeline figures
- gigawatt or capacity numbers
- deal counts
- customer or counterparty names

This applies to article deks and any site copy.

---

## 6. Tags

Filing metadata only. Tags are never rendered, never styled, and never enter
the markup. They exist so entries can be sorted and located, nothing more.

---

## 7. Sitemap

- Bump `<lastmod>` on the homepage entry only.
- Substack URLs never enter `sitemap.xml`. They live on a different domain,
  and listing foreign URLs in your sitemap is harmful, not neutral.

---

## 8. Writing entry template

Insert newest first, directly beneath `<p class="writing-intro">`.
Copy this block exactly and substitute the four values.

```html
    <div class="article">
      <a class="article-title" href="ARTICLE_URL">ARTICLE_TITLE</a>
      <p class="article-desc">DEK</p>
      <p class="article-date">DATE</p>
    </div>
```

Rules for the substitution:

- `DEK` is used verbatim as supplied. Do not rewrite, trim, or improve it.
  If it contains an em-dash, flag it and stop. Do not silently fix it.
- `DATE` currently renders as a bare year (for example `2025`).
  See TODO in section 11.
- No class names are added or changed. No inline styles.

---

## 9. Deploy procedure

1. Edit `index.html` (and `sitemap.xml` lastmod) on `main`.
2. Commit and push to `main`.
3. CI (`.github/workflows/publish.yml`) rebuilds `gh-pages` automatically.
4. Report the commit SHA and exactly what was added.

Verification is handled externally by the article-writing session, which
fetches the live URL after each push. Do not claim a deploy is live from
inside a sandboxed session; report what was pushed and let verification
close the loop.
